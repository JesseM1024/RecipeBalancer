> 流程图按配方依赖 SCC 分层，配方节点 + 物流边可滚动。81 项测试全绿。

## 一、做什么

把本机 Python 项目《配方树自动配平》（`C:\Users\JesseTech\Desktop\JesseTech\code\py\配方树自动配平`）
里的**稳态物料衡算求解器**移植为 **MC 1.21.1 + NeoForge 21.1.209 纯客户端模组**：

- 按下快捷键 → 打开游戏内图形界面；
- 配方数据**可视化录入**：原料/产物可从背包或 JEI 拖入标记，或**从 JEI 配方一键写入**
  （配方物品与数量自动带入，**配方耗时与设备种类手动填写**，与 Python 版语义一致）；
- 输入其余配置（目标产物与速率、外部原料、循环亏损白名单、求解目标……）；
- 求解：LP 稳态速率、机器并行数、外部输入、副产物；**支持循环配方**
  （SCC 亏损检测 + 完美循环最小启动投料）；
- 可视化在**游戏内原生渲染**（`GuiGraphics` 流程图 + 原生表单）；需要 HTML 时导出到浏览器查看
  （渲染主线与 JCEF 备选见 ARCHITECTURE.md §二）。

## 三、验收标准

### 求解（与 Python 版数据保真对齐）

| # | 标准 |
|---|---|
| A1 | 求解结果与 Python 版金标准（`tests/golden/` 9 场景）满足对拍层级 L1–L3（见 ARCHITECTURE.md §7）；L4 逐位速率在 LP 多解情形下不强求，但须记录差异原因 |
| A2 | 场景 JSON 与 Python `io.py` schema **完全同构**：Python 导出的场景可直接导入本模组求解，反之亦然 |
| A3 | 循环配方支持：SCC 亏损检测、`1→2` 自增殖种子、完美循环最小启动投料（含「不解析物品名，只看 sourceList/productList 结构与流量」的硬规则） |

### 交互

| # | 标准 |
|---|---|
| B1 | 快捷键打开/关闭界面（默认键位进键位设置菜单，可改） |
| B2 | 原料/产物槽可从**背包点选**标记物品；装有 JEI 时可从 **JEI 物品列表拖拽**到配方槽 |
| B3 | 装有 JEI 时，可对某物品**一键写入其 JEI 配方**（物品与数量自动带入）；耗时与设备类型手动填写 |
| B4 | 未安装 JEI 时全部功能照常可用（仅缺失 B2 拖拽 / B3 写入通道） |

### 渲染

| # | 标准 |
|---|---|
| C1 | 界面为**游戏内原生 GUI**（`GuiGraphics` + 原生控件），鼠标/滚轮/键盘/粘贴全可用 |
| C2 | 流程图可视化（`GuiGraphics` 绘制；节点配色语义与 Python pyvis 版一致：绿=外部输入 蓝=中间产物 黄=副产物 红=启动库存 紫=目标 橙=配方） |
| C3 | 可视化不可用（布局失败 / 场景过大）时退文本报告，编辑、求解、持久化功能保底 |
| C4 | 中文输入走原生 `EditBox`（IME 与粘贴可用，不再有 OSR 降级通道问题） |
| C5 | 可导出自包含 HTML（内嵌 vis-network；单文件、双击浏览器可看），供外部查看流程图 |

### 工程

| # | 标准 |
|---|---|
| D1 | 求解核心 `core/` 为纯 Java、零 MC 依赖，可在不启动游戏的情况下跑金标准 JUnit 测试 |
| D2 | 每轮改动：先入档实测结果为一个 git 提交，再动代码（沿用既有工作节奏） |
| D3 | 本模组不向任何服务端发送数据、不写游戏存档；场景数据存于 `config/recipebalancer/` |

## 四、非目标（明确不做）

- 不做服务端/多人同步；
- 不自动读取模组机器的**实际**配方数据库（GTCEu 等模组内部配方管理器不做对接）——
  录入路径只有：手动 / 背包 / JEI；
- 不做 1.20.1 等其它版本线（本模组与 logiscope 是**独立项目**，不共享代码）；
- 不解析物品名称/化学式做语义判断（幻想物质友好性，硬规则）；
- **本轮不做游戏内 HTML/CEF 渲染**（JCEF 降为备选、暂缓，恢复条件见 ARCHITECTURE §二）。
